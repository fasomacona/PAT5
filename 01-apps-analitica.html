5.1 Desarrollo de aplicaciones de analítica de datos

Una aplicación de analítica permite a usuarios (analistas, gerentes, clientes) explorar datos, ver indicadores y, en muchos casos, obtener predicciones sin escribir código. En este curso usaremos principalmente Streamlit (rápido para dashboards) y mencionaremos Flask para APIs/web clásica.

1. Arquitectura típica

  1. Fuentes de datos: CSV, Excel, SQLite/PostgreSQL, APIs.
  2. Capa de procesamiento: Pandas, limpieza, features (Tema 1).
  3. Capa analítica: estadísticas y modelos (Tema 3).
  4. Capa de presentación: gráficos + UI web (Temas 2 y 5).

2. Streamlit vs Flask

AspectoStreamlitFlask
Curva de aprendizajeMuy bajaMedia

UIComponentes listos (sidebar, charts)Plantillas Jinja + CSS/JS

3. Estructura de proyecto recomendada

proyecto_analitica/
├── app.py                 # punto de entrada Streamlit
├── src/
│   ├── data_load.py       # lectura CSV / SQL
│   ├── cleaning.py        # limpieza (Tema 1)
│   ├── features.py
│   ├── models.py          # entrenamiento / carga de modelo (Tema 3)
│   └── viz.py             # funciones de gráficos (Tema 2)
├── data/
│   └── ventas.csv
├── models/                # .joblib o .pkl
├── sql/
│   └── schema.sql         # (Tema 4)
├── requirements.txt
└── README.md

4. Hola mundo en Streamlit

import streamlit as st
import pandas as pd

st.set_page_config(page_title="Analítica", layout="wide")
st.title("Dashboard de ventas")

df = pd.read_csv("data/ventas.csv")
st.dataframe(df.head())

ciudad = st.sidebar.multiselect("Ciudad", df["ciudad"].unique())
if ciudad:
    df = df[df["ciudad"].isin(ciudad)]
st.metric("Total ventas", f"${df['monto'].sum():,.0f}")

5. Buenas prácticas

  • Separa lógica de negocio de la UI.
  • Cachea datos y modelos (@st.cache_data, @st.cache_resource).
  • No hardcodees rutas absolutas; usa rutas relativas al proyecto.
  • Documenta supuestos y limitaciones en la propia app.
