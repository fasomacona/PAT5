5.3 Desarrollo y presentación del proyecto práctico

El proyecto final demuestra que puedes resolver un problema de negocio con datos, de extremo a extremo, y comunicar resultados con claridad.

1. Fases del proyecto

  1. Problema y objetivo — pregunta de negocio medible.
  2. Datos — fuentes, calidad, diccionario de variables (T1, T4).
  3. Preparación — limpieza, features, train/test (T1).
  4. Exploración — estadísticas y visualizaciones (T2, T3).
  5. Modelado — línea base, modelos, métricas, validación (T3).
  6. Persistencia — opcional: guardar en SQLite / cargar desde BD (T4).
  7. Aplicación — dashboard o app con filtros y predicción (T5).
  8. Presentación — problema, método, resultados, límites, siguientes pasos.

2. Entregables sugeridos

  • Repositorio GitHub con código, datos de ejemplo y README.
  • Notebook de análisis (reproducible).
  • Aplicación Streamlit funcional.
  • Informe breve (PDF o Markdown) o diapositivas de presentación.

3. Rúbrica orientativa

CriterioPeso orientativo
Claridad del problema y del objetivo10%
Calidad de limpieza y preparación de datos15%
Análisis exploratorio y visualizaciones15%
Modelado y evaluación rigurosa20%
Integración en aplicación20%
Código limpio, documentado y reproducible10%
Presentación y conclusiones10%

4. Ideas de proyecto (ejemplos)

  • Predicción de churn / abandono de clientes.
  • Pronóstico de ventas por producto o región.
  • Clasificación de riesgo crediticio simplificado.
  • Dashboard de calidad de datos + alertas.
  • Análisis de tickets de soporte y priorización.
💡 Consejo Prefiere un problema acotado bien resuelto a un alcance enorme a medias. Un MVP claro supera a un prototipo incompleto de “todo”.
